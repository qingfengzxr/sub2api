# Claude Code CLI 样本验证矩阵

整理日期：2026-10-17。范围：`cc_version` 后缀、HTTP 请求特征、入口准入、请求改写与回退、HTTP/TLS 传输行为。

本机执行结果见 [2026-10-17 验证报告](CLAUDE_CLI_VALIDATION_RESULTS_2026-10-17.md)。本清单保留原始验证目标；不要将清单中的目标当成已经覆盖。

这是一份待执行的覆盖清单，不是验证通过报告。覆盖目标是声明支持的 CLI 版本、平台和配置；输入空间无限，不能由有限样本证明“所有版本、所有场景完全一致”。任何未捕获的行为都保留为未知。

共 11 类、159 组用例：P0 82 组、P1 75 组、P2 2 组。每组还需按长度、平台、版本、配置等条件展开，159 不是实际请求总数。

## 1. 验证原则

1. **真实客户端作参照。** 后缀期望值来自固定版本、固定二进制的原始 CLI 请求；不得用项目算法算出期望值，再验证项目算法自身。
2. **区分证据。** 原始 CLI 抓取、由其派生的负例、人工构造的结构测试、项目单元测试分别记录，不能相互替代。
3. **验证三层。** A：后缀与输入关系；B：请求内容与 HTTP 字段；C：实际发送的 HTTP/TLS 行为。每层独立给结论，A 通过不代表 B/C 通过。
4. **先保留原始数据，再做脱敏副本。** 参与后缀计算的正文、版本和顺序不得在保留旧期望值的同时被修改。生产凭据、真实用户内容不进入样本库；仅使用合成内容和专用测试身份。
5. **区分自然差异和项目改写。** 先抓 CLI 直连参照，再抓同一环境经项目转发的结果。认证凭据替换、明确配置的身份隔离属于有理由的差异，必须逐字段登记，不能用宽泛的忽略规则掩盖。
6. **不要把三位后缀当签名。** 三位十六进制只有 4096 种结果，碰撞不能证明算法成立或客户端来源可信。复制完整请求的脚本也可能满足格式校验。
7. **不从错误码推断风控。** 400、401、403、429 的出现或消失都不能单独证明官方客户端识别或指纹一致。

## 3. 执行与记录约定

### 3.1 优先级与状态

- **P0：发布门槛。** 声明支持环境的基础请求、已知回归、核心拒绝边界，必须完成。
- **P1：扩大覆盖。** 常见功能、多平台、代理与重试，进入相应支持范围前必须完成。
- **P2：探索。** 长尾配置、历史协议与大规模组合；有实际用户依赖时提升为 P0/P1。
- 状态统一使用 `pending`、`captured`、`passed`、`failed`、`unsupported`、`blocked`。`captured` 不等于已完成比较；`unsupported` 必须有支持范围说明，不能算通过。
- 每条矩阵行是一组用例，展开的每个变体都生成独立 `case_id`，例如 `TXT-02.len-04`、`NET-03.proxy-https`。

### 3.2 每条结果必须包含

| 字段 | 内容 |
| --- | --- |
| `case_id` / `variant` | 下表 ID 和展开条件 |
| `status` / `evidence_kind` | 执行状态；`cli_capture`、`derived_mutation`、`synthetic` 或 `project_test` |
| `captured_at` / `source` | 带时区时间；来源是实际 CLI、Agent SDK，还是项目构造，三者不可混写 |
| `cli_version` / `binary_sha256` | 版本命令输出、实际二进制或发行包校验值 |
| `install_method` / `platform` | 原生/包管理器/其他发行方式、OS/架构、相关运行时；记录实际观察而非硬编码推断 |
| `invocation` / `environment` | 完整参数、工作目录、配置来源、功能开关；环境变量只允许白名单，禁止全量导出 |
| `auth_mode` / `network_path` | 虚假 API Key、专用测试 API Key、受控 OAuth 等；直连/代理/证书环境，不保存秘密值 |
| `scenario` / `model` | 请求用途、会话阶段、实际模型标识与能力开关 |
| `original` | 请求序列号、原始 body 字节与 SHA-256、经过秘密字段清理的原始 header 序列、路径和方法 |
| `expected` / `actual` | 原始 CLI 后缀、项目计算后缀；CLI 请求与转发请求的结构化差异；网络层独立结论 |
| `allowed_diffs` | 每条允许差异的精确字段、理由、责任配置；禁止忽略整个 system/metadata/header 组 |
| `artifacts` / `verification` | 证据文件路径、测试命令、退出码、日志；复核人或复核记录 |

推荐目录：`testdata/claude-cli/<version>/<platform>/<case_id>/`。原始认证字段在写盘前移除；确需 OAuth/真实服务的测试在隔离环境执行，抓取器不得把凭据写入日志或提交仓库。脱敏导致正文变化的样本不得沿用原后缀期望值。

### 3.3 分阶段运行

1. **离线与回环阶段：** 使用合成输入和虚假凭据。验证首个请求、字段构造、拒绝逻辑与本地 TLS/HTTP 行为，不声称覆盖真实 OAuth 或多轮生命周期。
2. **脚本化响应阶段：** 本地服务模拟成功、工具调用、流式响应、重试错误与断流，驱动后续请求；记录响应脚本版本。
3. **受控端到端阶段：** 仅对需要真实认证/能力的用例使用专用测试账户，设置预算，比较完整实际链路。不得将模拟响应结果写成真实服务能力已通过。
4. **版本/平台扩展阶段：** 建立支持列表，每个支持单元分别重放 P0 样本；对高风险交叉组合执行 P1。

### 4.10 实际 HTTP/TLS 与代理路径

传输对比必须使用同版本、同平台、同目标形态和同代理路径。TLS 随机数、临时密钥、会话票据、请求 ID 等天然动态值不能直接逐字节比较，但每个归一化项都必须列出。HTTP/1.1 与 HTTP/2 不混为一组。

| ID | 优先级 | 样本/展开方式 | 比较与通过条件 |
| --- | --- | --- | --- |
| NET-01 | P0 | CLI HTTP 回环直连 vs 项目实际出站到相同捕获器 | 对端记录方法、path/query、原始头序列、body bytes；完成真正 wire 验证 |
| NET-02 | P0 | 本地可信证书 TLS 目标，CLI 直连 vs 项目出站 | 记录双方实际 ClientHello 与协商协议，不能从模板名称推断一致 |
| NET-03 | P1 | HTTP CONNECT、HTTPS proxy、SOCKS5、SOCKS5h | 每条代理路径各跑成对捕获；标明代理可能终止 TLS 的边界 |
| NET-04 | P0 | TLS profile 关、内置、绑定配置、随机配置、配置失效 | 不同路径分别给结论；随机 profile 不可默认宣称等同当前 CLI |
| NET-05 | P1 | TLS 版本、cipher/extension 顺序、groups、签名算法、ALPN | 比较归一化结构；单个 JA3/JA4 相等不证明全部一致 |

| NET-07 | P1 | HTTP/2 SETTINGS、伪头顺序、流/窗口行为 | 仅对实际 h2 路径执行；分别比较连接层和请求层 |
| NET-08 | P1 | 连接复用、连续请求、空闲后再用、TLS resumption | 区分冷连接与热连接的正常差异，记录连接状态 |
| NET-09 | P1 | gzip/br/zstd 等声明与实际请求/响应压缩 | 只展开 CLI 实际支持的形式；正确解码且不改变内容语义 |
| NET-10 | P1 | IPv4/IPv6、DNS 解析失败、代理远端解析 | 确认出站确实经过预期代理，失败不静默绕过代理直连 |

## 5. 组合覆盖与执行规模

不建议把所有维度直接做笛卡尔积，也不允许只跑一个“Mac + bare + 英文 + 单轮”后声称全面覆盖。

| 执行批次 | 必做组合 | 覆盖目的 |
| --- | --- | --- |
| 首批 P0 | 当前主用 CLI/平台 × ASCII/中文/边界 emoji × 首轮/多轮/工具结果/compact（如支持） | 先关闭已知 Unicode 与消息提取风险 |
| 支持基线 | 每个声明支持的版本/平台/认证单元 × 全部适用 P0 | 防止某一平台的 profile 被推广到全部环境 |
| 改写分支 | messages/count_tokens × identity 开/关 × metadata 透传开/关 × 冷/热/错误缓存 | 对参与出站构造的布尔开关执行全组合，归档每个差异 |
| 回退分支 | 普通/专用/综合入口 × CLI/非 CLI/歧义 JSON × 无回退/Anthropic 回退 | 完整 handler 集成验证准入不丢失也不误拒 |
| 传输分支 | 各支持网络路径 × TLS profile 关/开 × 冷/热连接 | 确认真实网络路径，没有 HTTPS 代理等特殊退化漏测 |
| 其余配置 | 版本、OS、安装方式、模型、功能开关使用 pairwise，再增加下面的三维组合 | 扩大交互覆盖；pairwise 通过不代表所有组合通过 |

必须额外执行的高风险组合：

- Unicode 边界 × 多 text block × 空块清理。
- 中文/emoji × compact 后历史 × billing 同步。
- OAuth × metadata 重写 × 多账号 failover。
- 两个 CLI 版本 × 共用账号热缓存 × 并发。
- 强制 Antigravity 路径 × 不同所属分组 × Anthropic 回退。
- 超限/歧义正文 × 中间件预读 × 回退。
- HTTPS proxy × TLS profile 开启 × 重试。
- 版本自动同步 × 进行中的请求 × 出站 profile 应用。

稳定性最低要求：每个固定用例在同环境重复 3 次；用于判断是否依赖会话/进程的用例按 TXT-22 执行。首轮 Unicode 探索可设固定种子 200 个样本；每个失败样本至少增加 3 个邻近变体，保留最小反例。数量只描述本批执行规模，不是算法正确性的数学保证。

## 6. 完成标准与报告

### 6.1 单例完成标准

- 真实 CLI 样本有可追溯版本、启动参数、原始请求和期望值；人工构造用例明确标记。
- 同一输入的期望来源独立于项目实现，所有实际发送请求都有接收端证据。
- billing 检查完整文本与完整后缀；头部不只检查挑选出的字段。
- 正文逐字段、逐块检查；原始字节比较与语义比较分别报告，不用 JSON 重排抹掉线序差异。
- 随机值/ID 既验证结构也验证稳定性关系；不简单删除后再比较“相等”。
- 每条允许差异都有理由和配置来源；差异发生后不得报告“完全一致”。
- 拒绝用例以“没有调用 Anthropic 上游”为关键断言；只收到 403 不足以证明没有先发送。
- 回退、重试、工具与多轮用例验证完整请求序列，不能只看第一条。

### 6.2 发布门槛

所有声明支持单元的 P0 都有结果；无未解释失败、无用合成期望冒充真实 CLI 输出；风险较高的 P1 在启用对应功能前完成。阻塞/不支持项单列，不能从分母移除来提高通过率。

分别输出三项结论：

1. **后缀层：** 在哪些 CLI 版本、哪些文本/结构样本中匹配；未知依赖和反例是什么。
2. **HTTP 层：** 哪些字段一致、哪些按设计改写、哪些请求类别仍未知。
3. **传输层：** 哪些版本/平台/代理路径已成对验证；哪些仅测了模板或未验证。

格式准入单独给结论：它检查可观察的请求格式，不能认证进程来源。若业务要求“只有受信调用方能请求”，需要独立的调用方认证与授权控制；不得把该目标记作后缀样本验证通过。
