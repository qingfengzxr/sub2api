# 模型响应中的计费用量

启用「billable token 计费」后，生成接口返回的标准 usage 采用本次请求的计量策略。普通输入和输出按设置的倍率分别向上取整；缓存读取、缓存写入及其期限明细使用原始数量。倍率为 1 或功能关闭时不放大；发生强制缓存计费时，输入仍会按实际计费分类显示。

OpenAI Responses 和 Chat Completions 的输入总量包含缓存；Claude 的 `input_tokens` 不包含缓存；Gemini 的 `promptTokenCount` 包含缓存，输出计量包含候选与思考 token。流式接口在提供 usage 的事件中返回相同口径；WebSocket 连接中的每一轮单独固定倍率，设置变更从下一轮开始生效。

Gemini 同时返回多种输入模态时，只有上游提供足够的缓存模态明细，平台才能准确调整各模态用量；否则保留上游模态明细，以总量为准。

平台记录保留计费用量及用于结算的用量，管理员可用于核对；强制缓存计费时，记录中的输入按现有规则重新归类为缓存读取。Grok Chat 图片桥接产生额外上游调用时，最终用量按结算口径合并。上游没有返回 usage 时，平台不会据此推算完整用量。返回的 usage 不是扣款成功的凭证，异步记账结果以平台账单为准；按次、按图片数量及其他非 token 费用也不能完整体现在 token usage 中。

官方 Embeddings 使用上游原始用量，不受该倍率影响。`countTokens` 等估算接口保持原语义。计量设置读取失败时，生成请求在调用上游前失败，请稍后重试。
