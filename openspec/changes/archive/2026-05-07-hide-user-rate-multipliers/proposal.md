## Why

当前用户侧页面和接口会直接展示分组倍率，例如 `3x`。这会让运营定价策略暴露给普通用户，尤其当倍率较高时难以解释，也会削弱产品对外展示的专业性和灵活定价空间。

## What Changes

- 隐藏普通用户侧所有分组倍率、用户专属倍率和图片倍率的直接展示。
- 普通用户侧仍可看到分组名称、平台、订阅类型、可用状态、限制说明和价格/额度等面向用户的解释性信息。
- 本次改动仅调整 C 端普通用户体验和用户侧字段暴露；管理员后台体验、管理员 API、管理逻辑、倍率配置能力、用量核算和内部日志中的倍率逻辑保持不变。
- 为降低上游同步成本，本次只做最小后端收敛：隐藏 `/api/v1/keys` 响应中嵌套分组的倍率字段，并让 `/api/v1/groups/rates` 不再向普通用户返回真实倍率。
- 前端用户侧不再展示 `x倍`、`rate multiplier` 或等价文案，改为展示“标准”“高级”“订阅”“按实际用量计费”等产品化描述。
- 暂不全面改造其他用户侧 API DTO；后续如发现其他 C 端页面仍泄露倍率，再按独立小改动处理。
- **BREAKING**：如果外部客户端依赖 `/api/v1/keys` 或 `/api/v1/groups/rates` 读取普通用户倍率字段，需要改用管理员接口或内部接口；普通用户接口不再承诺返回这些倍率值。

## Capabilities

### New Capabilities
- `user-facing-rate-visibility`: 覆盖普通用户侧隐藏内部计费倍率、保留管理员和内部计费倍率能力、以及用户侧产品化展示规则。

### Modified Capabilities

无。当前项目中尚未定义已有 OpenSpec 能力。

## Impact

- 影响后端 C 端用户 API：`/api/v1/keys` 中嵌套 group 的倍率字段，以及 `/api/v1/groups/rates` 的真实倍率返回。
- 影响前端 C 端用户页面：API Key 管理、可用渠道、用量详情、支付/订阅页面中倍率展示文案。
- 不影响管理员后台体验、管理员 API、倍率配置、用户专属倍率配置、计费计算和用量核算。
- 不影响数据库 schema；优先通过前端展示逻辑、`/api/v1/keys` 专用响应收敛和 `/api/v1/groups/rates` 返回策略实现。
