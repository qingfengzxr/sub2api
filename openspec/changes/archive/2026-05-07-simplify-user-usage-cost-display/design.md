## Context

`UsageView.vue` 当前在 C 端使用记录页展示多个费用口径：总消费卡片显示最终扣费金额，同时用“实际 / 删除线标准”展示标准计费；表格费用 tooltip 也展示“原始”和“计费”。这些字段会让普通用户感知到标准价、最终价、倍率或折扣等内部计费口径差异，与“C 端用户只需要知道最终结果”的产品目标不一致。

本次变更限定为前端展示调整。后端仍可返回 `total_cost`、`actual_cost` 等字段，管理员侧和导出逻辑不受影响。

## Goals / Non-Goals

**Goals:**

- C 端使用记录总消费卡片只展示最终总消费金额。
- C 端费用 tooltip 不展示“原始”“计费”或等价双口径消费字段。
- 保留用户可理解的最终费用、Token、耗时、模型、端点等使用信息。
- 最小化前端改动，不改变数据请求、计费计算、扣费和管理员体验。

**Non-Goals:**

- 不修改后端 `/api/v1/usage` 或统计接口响应结构。
- 不改变 `total_cost`、`actual_cost` 的入库、聚合、导出或管理员侧展示含义。
- 不调整倍率、定价、余额、订阅额度或用量计算逻辑。

## Decisions

- 使用现有最终扣费字段作为 C 端展示金额：总消费卡片继续以 `total_actual_cost` 展示，表格费用继续以 `actual_cost` 展示。这样不影响后端契约，也避免用户看到标准价。
- 移除用户侧双口径文案而非隐藏整个 tooltip：tooltip 可以保留 Token 成本、单价、缓存等非倍率明细，但不能出现“原始/计费”“实际/标准”这类成对口径。这样既减少倍率暗示，又保留排查单次请求费用的必要信息。
- 不复用管理员侧费用口径文案扩展 C 端说明：管理员侧可继续查看内部标准价、倍率和多口径分析，C 端文案应围绕“费用/消费/总消费”表达最终结果。

## Risks / Trade-offs

- 用户无法从 C 端直接比较标准费用和最终扣费差异 → 符合隐藏倍率细节目标；需要内部排查时使用管理员侧页面或数据库。
- 前端仍接收 `total_cost` 字段 → 本次是前端-only 展示收敛，不解决接口层字段暴露；接口层已由既有隐藏倍率变更覆盖指定用户接口。
- tooltip 保留部分成本明细可能仍展示标准拆分成本 → 实现时需确保不出现成对原始/最终口径字段；如产品希望彻底隐藏成本明细，可后续单独收敛。
