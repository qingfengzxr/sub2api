## Why

用户密钥目前只能配置 5 小时、1 天和 7 天的消费速率限制，无法限制长期累计消费。需要在编辑密钥时增加月度限额，让用户可以控制单个密钥在连续 30 天窗口内的最大 USD 消费。

## What Changes

- 在用户“编辑密钥”的速率限制区域增加“30天限额 (USD)”输入项。
- 为 API 密钥增加 30 天限额、当前窗口用量和窗口开始时间，沿用现有固定窗口累计与到期重置模型。
- 扩展密钥查询和更新 API，返回并接受月度限额；`0` 表示不限制，未提供字段表示不修改。
- 在请求鉴权、费用预检、扣费累计、缓存和手动重置链路中加入 30 天窗口。
- 保持现有 5 小时、1 天和 7 天限速语义及旧客户端行为不变。

## Capabilities

### New Capabilities

- `api-key-monthly-rate-limit`: 用户可为单个 API 密钥配置连续 30 天 USD 消费限额，并在达到限额后阻止继续消费。

### Modified Capabilities

None.

## Impact

- 前端用户密钥页：编辑弹窗、表单状态、类型、API payload 和国际化文案。
- API 密钥接口：列表/详情响应与更新请求增加 `rate_limit_30d`；输入校验保持非负有限数规则。
- 后端领域与持久化：API Key 模型、Ent schema、数据库迁移、仓储映射和原子用量更新增加 30 天窗口字段。
- 鉴权与计费：认证缓存、Redis 限速缓存、网关预检、费用累计和限速错误响应增加月度窗口处理。
- 测试：覆盖更新、限额拒绝、原子累计、缓存、重置和编辑交互。
- 不新增第三方依赖，不改变现有 API 路由。
