# 方案复审：正确性与低耦合实现

日期：2026-10-12。基线：`cooper/dev` / `8db8d322e`。范围：原方案、现有调用链与公共接入点；本次只修订规划，以下实现问题尚未修复或通过运行测试验证。

结论：可以沿用现有 Embeddings 架构实现，但原方案不能直接作为完整施工清单。新增逻辑应集中到专用文件，计费、审计仍需要少量明确的公共接入，不能以完全不碰主干文件为目标。

## 发现与修订

## 复用确认

- 路由、调度器、并发、URL 拼接、HTTPUpstream、账务仓储与使用量队列都有现成实现；无需新增替代系统或改依赖注入图。
- 价格服务已有确定性查价能力和 `ResolvedPricing` / `CostInput.Resolved`；不要复制通用算价公式，也不要仅凭 `GetModelPricing != nil` 判定模型精确定价有效。
- Ops 对 HTTP 200 存在 `logOpsRecoveredUpstream` 路径；成功响应异常并非必然被忽略，但必须测试监控开关、过滤与队列行为。设置 Gin 变量不等于数据已落库。
- 当前已有第三方 Embeddings 扩展。严格参数、Usage 和价格策略按有效官方模型隔离；平台防御仍覆盖整个 Embeddings 入口。

## 模块化验收门槛

1. 协议和用量函数可用输入/输出独立测试，不依赖 Gin、数据库、Redis。
2. 只保留一套模型映射、一套费用公式、一套扣费/用量落库；不复制公共代码以追求“零公共 diff”。
3. 新计费输入通过明确的可选字段传递，缺省行为不变；不把价格/模型决策隐藏到 context key，不修改共享缓存对象。
4. 新增逻辑和测试按 Embeddings 归档；公共文件没有无关格式化、搬迁和全局策略改写。
5. 每个公共接入均有两个方向的契约测试：Embeddings 新语义生效，普通对话或第三方路径保持原样。
6. 实现交付列出公共接入点和合并后需重跑的测试，而非仅提供“改动多少文件”。文件数不是耦合度指标。

## 保留的限制

- 缺少真实 Usage 仍不能可靠计算 token 费用；异常检测不是自动补账。
- 必达工作池提交不是持久化消息队列，进程崩溃/数据库长期不可用的账务保障沿用项目现状。
- 审计的“检测但不保留正文”若需从异步改为同步，会增加此端点延迟；只能在原请求总预算内执行，且必须保留现有审计失败策略。
- 公共账务与安全接入无法做到完全零冲突；本方案将其限制为可枚举、可验证的小范围变化。
